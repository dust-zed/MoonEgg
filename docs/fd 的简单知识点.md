## fd 是什么？
fd 是 file descriptor, 文件描述符，本质上是一个非负整数，例如`7`。它是当前进程文件描述表中的索引，系统通过它找到
对应的打开资源。普通文件、管道、socket 都可以用 fd 操作。

在 MoonEgg-Android中，Kotlin 和 Rust 运行在同一个进程中，使用同一张描述符表。

**复制 fd 后，实际关系是这样**：
```
Android 持有 fd 7 ──┐
                   ├──→ 同一份内核“打开文件状态” ──→ 文件
Rust 持有 fd 12 ────┘       包含当前偏移 offset
```

系统复制操作增加了一个新句柄，但让它指向原来的“打开文件状态”（open file description）。offset 保存在这份共享状态里，
而不是分别保存在 fd 7 和 fd 12 里。

### 独立关闭是什么意思

假设 fd 复制成功后：
- Android 关闭 `7`，Rust 的`12`仍然有效。
- Rust 的`File`被释放时关闭`12`, 不会再去关闭`7`。
- 最后一个引用关闭后，内核才释放相应的打开文件状态；这不等于删除磁盘文件。
这里 `File` 自动管理的是**fd 12 的关闭责任**，并没有独占底层文件状态。

### 共享位置的表现

假设文件足够长，初始偏移为零：
| 操作 | 共享偏移 |
|---|---:|
| Android 通过 fd 7 读到 100 字节 | 100 |
| Rust 通过 fd 12 再读到 20 字节 | 120 |
| Rust 通过 fd 12 定位到 500 | 500 |
| Android 下一次读取 | 从 500 开始 |

所以我们项目中的使用方式应当是：
```
Android 打开资源
    → 同步调用 Rust，Rust 完成 fd 复制
    → Android 可以关闭自己的句柄
    → 后续由 Rust 负责读取
```

这解决了 Android 资源对象关闭后，Rust 仍需继续播放的问题。**复制 fd 不会自动防止重复关闭；避免重复关闭靠的是“每个句柄只交给一个所有者”**。
再区分一个很容易混淆的操作：
```rust
let copied_fd = fd; // 只复制整数，仍是同一个句柄编号
```
它没有向系统申请新句柄。我们调用 `fcntl` 才是真正复制描述符。
如果对同一路径重新调用一次 `File::open`，通常会产生另一份打开文件状态，拥有独立的偏移；而 `try_clone` / `fd` 复制仍然共享原来的状态
