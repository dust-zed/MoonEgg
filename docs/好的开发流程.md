### 1. 先弄清数据流

```
媒体源
  → Demuxer
  → Packet
  → Decoder
  → DecodedFrame
  → AudioOutput / VideoOutput
```
这一步回答“数据怎么走”，不着急写具体实现。

### 2. 定义最小数据模型

例如：
```
Timestamp
Packet
TrackInfo
DecodedFrame<T>
AudioBuffer
```
结构体重点表达领域事实和不变量：
```
Packet 有所属轨道
时间戳带有 time_base
AudioBuffer 包含整数个 audio frame
硬件 token 不能随意复制
```

### 3. 在真实边界处定义 trait

trait 适合出现在 “实现可能被替换”的地方
```
Demuxer：不同容器或库
Decoder：软件解码或 MediaCodec
AudioOutput：AAudio、AudioTrack、桌面音频
VideoOutput：Android Surface、桌面窗口
```

### 4. 尽快写一个最小实现验证契约

trait 不能长期停留在想象中。接口是否合理， 往往要到实现时才能发现：
```
Packet 所有权丢失怎么办？
硬件解码器输入满了怎么办？
一次 Packet 不产生 Frame 怎么办？
AudioTrack 只接受了一部分 PCM 怎么办？
设备播放位置如何映射到 MediaTime？
```
